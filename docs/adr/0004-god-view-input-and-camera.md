# ADR 0004：上帝视角输入与相机标定

状态：已采纳（源自 Gitea 票 #8 D1–D5、#10 探针、#19 真机标定）

## 背景

玩法是固定俯视棋盘上的点击放置。SE 客户端需要把触摸位置换算为棋盘坐标再交给服务端。真机探针发现：`ViewportPointToRay` 无视入参不可用；`UserInputService:GetMouseLocation` 在编辑器试玩里恒为 (0,0)；EUI 画布与相机视口是两个不同像素空间，原点与 y 方向相反，只按比例缩放。

## 决策

1. 相机：`CameraMode.NONE` 定点，高度 60、俯仰 +90（正值为俯视）、FOV 45，`ManualRefresh` 生效。不写 `Priority`（真机触发宿主警告且无必要）。启动 1 秒后首写并连写 2 帧，之后每 5 秒重申。
2. 坐标换算：EUI 画布坐标 × 标定比例 k → 相机屏幕像素 → `ScreenPointToRay` → 与棋盘平面 y=0 求交。k 在相机写入后延几帧标定：世界原点投影到视口中心，视口尺寸即 2 倍中心。
3. 输入捕获：全屏透明 `EUIImage`（Opacity 0 仍能命中）只认第一指。按下与移动发 hover 意图，松手发 tap 意图，不设位移阈值。
4. PC 辅路：右键与 Escape 发 cancel。右键抬起会触发捕获层的 ended，用 0.5 秒时间窗压掉那一次 tap。
5. 棋盘边界判定统一在服务端 `host.input`（由 `level_bounds` 注入），网络层只校验数值有限性，不重复边界。

## 后果

- 本图不需要相机平移或缩放手势，长拖即拖着预览放置，是触摸放置的自然语义。若日后引入相机手势，第 3 条要重新决策。
- 换算依赖运行时标定，标定前的 tap 一律无交点，客户端会在日志里标明"相机未标定"。
- 实现落在 `client/camera.lua` 与 `client/board_input.lua`，服务端校验在 `server/net.lua`。
